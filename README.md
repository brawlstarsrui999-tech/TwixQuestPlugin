# TwixQuestPlugin для TwixRPG 1.21.11

Плагин с фиолетовой тематикой, реализующий основное меню квестов с топом скорости,
деревом основных квестов и заготовкой для клановых.

## Особенности
- 35 готовых квестов, редактируемых через `plugins/TwixQuestPlugin/quests.yml`.
- **Квесты на предметы — через вложение.** Игрок кликает по квесту в дереве, и нужное
  количество предметов забирается из инвентаря (можно по частям, прогресс сохраняется).
- Автоматическое отслеживание остальных квестов: следующий стартует только после предыдущего.
- Дерево квестов на страницах (все 35 видны), окно «Информация о квесте» с настоящими предметами-наградами.
- Награды с цветными названиями и **настоящими чарами** (включая зачарованные книги).
- Прогресс хранится в файле игрока: не теряется при выходе и перезапуске сервера.
- Интеграция с Vault (монеты), PlayerPoints (Twixcoin) и BaerPlugin (продажа байеру).
- Клановые квесты — заглушка (WIP) с пояснением в меню.
- Топ игроков: 9 мест (медали за 1–3), сортировка по числу пройденных квестов,
  при равенстве — по времени. Отдельно показывается ваше собственное место.

## Как проходить квесты
Откройте `/quests` → «Дерево квестов». Выполненные квесты зелёные, текущий подсвечен, будущие закрыты.

| Действие в дереве | Что происходит |
|---|---|
| **ЛКМ по текущему квесту на предметы** | Из инвентаря забирается нужное количество (сколько есть — столько и вложится). |
| **ПКМ** по текущему или выполненному квесту | Окно «Информация о квесте»: цель, прогресс, награды. |
| Страницы | Если квестов больше 36, внизу появляются кнопки «Дальше»/«Назад по списку». |

- Вкладываются только «чистые» предметы: переименованные, зачарованные и с данными других плагинов квест не заберёт.
- Квесты «скрафтить X» засчитываются сами. Если предмет уже лежит в инвентаре — кликните по квесту:
  предмет **останется у вас** (его не забирают).
- «Зайти в Ад / Энд» работает через смену мира, а не через достижение: подходит и тем,
  кто достижение уже получил. Достаточно просто находиться в нужном мире, когда квест стал текущим.
- «Попасть в бастион» — достаточно оказаться внутри структуры.

## Установка
1. Бросьте `TwixQuestPlugin-1.0.0.jar` в папку `plugins/`.
2. Установите зависимости:
   - `Paper 1.21.11`
   - `Vault` (https://www.spigotmc.org/resources/vault.34315/)
   - `PlayerPoints` (https://www.spigotmc.org/resources/playerpoints.80745/)
   - `BaerPlugin` (`brawlstarsrui999-tech/BaerPlugin`) — для квестов на продажу байеру.
3. Перезапустите сервер. В `plugins/TwixQuestPlugin/quests.yml` будут все квесты.

**Обновление.** В `quests.yml` есть `config-version`. Если на сервере лежит файл с меньшей версией
(например, от старой сборки), плагин **сам заменит его новым**, а старый сохранит рядом как
`quests.yml.bak-v<версия>-<дата>` — свои правки можно перенести оттуда. Если вы правите файл вручную,
поднимите `config-version` выше вшитого, и плагин вас не тронет.

## Команды
- `/quests` (алиасы: `/quest`, `/twixquests`, `/tq`) — открыть меню квестов.
- `/tqadmin reload` — перезагрузка конфигурации.
- `/tqadmin reset <player>` — сброс прогресса игрока.
- `/tqadmin complete <player> <active|questId>` — завершить текущий/конкретный квест.
- `/tqadmin info <player>` — статистика игрока.

## Настройка квестов
Откройте `plugins/TwixQuestPlugin/quests.yml`. Поддерживаемые типы:

| Тип              | Описание                                                        | Поля                                       |
|------------------|-----------------------------------------------------------------|--------------------------------------------|
| `DEPOSIT_ITEM`   | **Вложить** предметы: клик по квесту забирает их из инвентаря   | `material`, `amount`, `extras`, `consume`  |
| `CRAFT_ITEM`     | Скрафтить предмет (засчитывается сам; клик — если он уже есть)  | `material`, `amount`, `consume`            |
| `KILL_MOB`       | Убить N определённых мобов                                      | `entity-type`, `amount`                    |
| `KILL_PLAYER`    | Убить игрока (жертва должна наиграть 30+ минут)                 | `amount`                                   |
| `ENTER_WORLD`    | Оказаться в мире (`world-env`: `NORMAL`/`NETHER`/`THE_END`)     | `world-env` или `world-name`               |
| `VISIT_STRUCTURE`| Оказаться внутри структуры                                      | `structure`, `world-env` (необязательно)   |
| `TRADE_VILLAGER` | Совершить сделку с жителем                                      | `amount`                                   |
| `SELL_TO_BUYER`  | Продать байеру (правый клик в `/buyer`)                         | `material`*, `amount`, `count-buys`        |
| `BUY_FROM_BUYER` | Купить у байера (левый клик в `/buyer`)                         | `material`*, `amount`, `count-buys`        |
| `REACH_BALANCE`  | Иметь на счёте Vault не меньше N монет                          | `amount`                                   |
| `MOUNT_STRIDER`  | Оседлать лавомерку                                              | `amount`                                   |
| `MINE_BLOCK`     | Сломать N блоков                                                | `material`, `amount`                       |

\* Если `material` не указан, засчитывается ЛЮБОЙ предмет сделки — удобно для квестов вида
«продайте что-нибудь байеру».

Общие поля: `name`, `description`, `icon` (материал иконки в меню; иначе подбирается по типу:
яйцо моба, сам предмет и т. д.), `silent` (`true` — не объявлять выполнение в чат).

### Квест на вложение предметов
```yaml
13:
  name: "Крылья мечты"
  description: "Вложите в квест 12 Ок Эндера и 6 стержней ифрита — и небо станет вашим."
  type: DEPOSIT_ITEM
  material: ENDER_EYE
  amount: 12
  extras:                    # дополнительные предметы, которые тоже нужно вложить
    - material: BLAZE_ROD
      amount: 6
  reward:
    items:
      - material: ELYTRA
        name: "<gradient:#D6B8FF:#6EE7D8><bold>Крылья Покорителя Края</bold></gradient>"
```
Прогресс по каждому предмету хранится отдельно, поэтому можно приносить предметы по частям.

### Награды
```yaml
reward:
  items:
    - material: DIAMOND_SWORD
      name: "<gradient:#FF5E3A:#FFC371><bold>Клинок Пламенного Дуэлянта</bold></gradient>"
      enchantments:          # ключи чар Minecraft: sharpness, fire_aspect, unbreaking, mending, wind_burst...
        sharpness: 4
        fire_aspect: 1
    - material: ENCHANTED_BOOK   # для книги чары кладутся внутрь книги
      amount: 2                  # книги не стакаются — выдаются отдельными предметами
      enchantments:
        mending: 1
  vault-coins: 1500          # монеты Vault
  twix-coins: 50             # Twixcoin (PlayerPoints)
  exp-levels: 30             # уровни опыта
  commands: [ "give %player% minecraft:cake" ]   # команды от имени консоли
```
- Предметы, которые не влезли в инвентарь, падают под ноги, но **подобрать их может только получатель награды**.
- **Ресурсам не давайте имя** (булыжник, слитки, жемчуг, ключи, стержни): именованный предмет не стакается
  с обычным, не подойдёт для вложения в другие квесты, а ключ испытаний с чужим названием может не открыть хранилище.
  Красивые названия — для экипировки и книг.

Цвета и форматирование используют [MiniMessage](https://docs.advntr.dev/minimessage/format.html):
поддерживаются HEX `#RRGGBB`, `<color:...>`, `<b>`, `<i>`, `<gradient:#..:#..>`, `<click:run_command:/foo>`, `<hover:...>`.

## Байер-интеграция
Плагин байера (`brawlstarsrui999-tech/BaerPlugin`, имя плагина в его plugin.yml —
`BuyerPlugin`) **менять не нужно** — TwixQuestPlugin работает поверх него.

Как устроен сам байер (проверено по его исходникам, `com.buyerplugin.ShopGUI`):

- `/buyer` (алиасы `shop`, `магазин`) открывает GUI на 54 слота с заголовком
  `Байер » <категория>`;
- **продажи через команду нет**: `/buyer sell` не существует. Продажа — это
  **правый клик** по товару, покупка — **левый** (shift — по 64 штуки);
- после каждой сделки байер переоткрывает своё окно (`refreshLater`), то есть
  Bukkit шлёт `InventoryCloseEvent` по старому окну и `InventoryOpenEvent`
  по новому.

Что делает TwixQuestPlugin:

1. отмечает «сессию байера» — по команде `/buyer` **или** по заголовку GUI
   (ключевые слова настраиваются в `settings` в `quests.yml`);
2. запоминает снимок инвентаря и баланс игрока;
3. на каждом закрытии окна (включая автообновление байером) и раз в секунду
   сравнивает снимок с текущим инвентарём: чего стало меньше — продано,
   чего больше — куплено, и передаёт это в `QuestManager.onBuyerTrade`;
4. баланс Vault используется только как подсказка «продажа это или покупка»,
   поэтому квесты считаются и без подключённой экономики.

Прогресс приходит в текущий квест: для `SELL_TO_BUYER` — по проданным предметам,
для `BUY_FROM_BUYER` — по купленным. Флаг `count-buys: true` заставляет квест
засчитывать и встречную операцию. Если в квесте не указан `material`, считается
любой предмет сделки.

Настройка распознавания байера (`plugins/TwixQuestPlugin/quests.yml`):

```yaml
settings:
  buyer-gui-keywords: ["байер", "баер", "buyer", "baer"]
  buyer-command-labels: ["buyer", "baer", "shop", "магазин"]
```

Если у вас стоит своя сборка байера с другим заголовком/командой — просто
допишите туда нужные слова, перезапуск не требуется (`/tqadmin reload`).

Для своих байер-плагинов остался и прямой мост через Bukkit `ServicesManager`:

```java
import twix.quest.hook.BuyerHook.TwixQuestManagerBridge;
TwixQuestManagerBridge bridge = Bukkit.getServicesManager().load(TwixQuestManagerBridge.class);
if (bridge != null) bridge.notifySell(player, Material.COBBLESTONE, amount);
```

## Оформление текста
Все строки идут через MiniMessage. Цвета — **незакрываемые** теги: пишите
`<#9B59FF>` или `<gold>` и НЕ пишите `</gold>`/`</#9B59FF>`. Такой закрывающий
тег MiniMessage не отбрасывает, а выводит обычным текстом — именно так в топе
появлялись строки вида `<##F1C40F>Медаль #1`. На всякий случай `TextUtil`
теперь сам чинит обе опечатки (двойная решётка и закрывающий цветовой тег)
и пишет предупреждение в консоль, а при совсем битой строке показывает текст
без разметки вместо падения меню.

## Сборка и тесты
```
mvn package        # собирает target/TwixQuestPlugin-1.0.0.jar и прогоняет тесты
```
Тесты работают на [MockBukkit](https://github.com/MockBukkit/MockBukkit) (эмулированный сервер): настоящий
плагин, игрок, меню, клики, инвентари. Проверяется в том числе, что `quests.yml` совпадает со списком квестов
и наград, что чары действительно попадают на предметы, что клик по квесту забирает ровно нужное
количество, что прогресс переживает перезапуск и что продажа через GUI байера засчитывается.
На GitHub та же сборка запускается автоматически (`.github/workflows/build.yml`).
